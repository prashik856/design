# Rest API

## Why rest is so popular?
API - Application Programming Interface

Way for two computers to talk to each other.

Most common way to do this i scalled REST.
REST - REpresentational State Transfer.

Rest is not a specification. 

Rest API Rules - 
- Uniform Interface
- Client - Server
- Stateless
- Cacheable
- Layered System
- Code on Demand (Optional)

API that follows the REST standard is called a RESTful API.

Twilio
Stripe
Google Maps

## Basics of REST
Rest API organizes resources in a set of unique URIs.
Example
- https://example.com/api/v3/products
- https://example.com/api/v3/users

URI (Uniform Resource Identifiers)

URIs differentiate different types of resources on a Server.

Example

client -> /products -> Server -> Product Database
        -> /users -> Server -> Users Database

Resources should be grouped by nouns, not verbs.
Example:
https://example.com/api/v3/products is correct way of getting all products.
https://example.com/api/v3/getAllproducts is wrong.

Client interacts with a resource by making a request to the endpoint of the resource
over HTTP.

The requests has to be in very specific formats.

The URI is preseeded with HTTP verb (GET, PUT, POST, DELETE) which tells the server what we
want to do with the resource.

E.g. POST /products HTTP/1.1 Accepts: application/json

POST request -> We want to create a new resource.
GET -> Read data of existing resource
PUT -> Updating an existing resource
DELETE -> Removing an existing resource.

CRUD - Create, Read, Update, Delete.

In POST request, we can have additional data in http request body.
It contains a custom payload of data, usually in json.

The Server processes the request, and form a HTTP Response
HTTP/1.1 200 OK

We return the status code which tells what happened to the request. 
Proper HTTP status code should be returned.

200 level -> Success
400 level -> Something wrong with our request
500 level -> Something went wrong with our server

Retry when we are getting 500 level status code.
This is because some items are not idempotent.

POST -> Not idempotent
GET -> Idempotent
PUT -> Idempotent
Delete -> Idempotent

Idempotent -> Making multiple identical request has the same effect as making a single request.

The Response body is optional, and it is usually formatted in json.

## Stateless Implementation
The REST Implementation should be stateless.
It means that the two parties do not need to store any information about each other.

Every request and response is independent of one another.

## A Good restful API

### Pagination
If API returns a huge amount of data, we should do Pagination.
Out API should accept limit and offset parameters in the API request.

E.g.
/products?limit=25&offset=50

If they are not provided, server should assume some default values.

### Versioning
Versioning of an API is very important.
Versioning allows implementation of backward compatibility.
If we introduce breaking changes in one version to another, consumers have enough time 
to move to next version.

There are many ways to version an API,
we can usually add the version before the resource on the URI
/v1/products
/v2/products
