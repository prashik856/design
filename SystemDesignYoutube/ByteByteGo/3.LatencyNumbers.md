We usually have this heirarchy in the CPU Cache:
Register -> L1 Cache -> L2 Cache -> L3 Cache (Shared) -> Local Memory

From Registers to L3 Cache, they come as a part of CPU Registers.


## 1ns
Accessing CPU registers

The Clock Cycle of a modern CPU is also in 1ns range.

## 1-10ns
We have L1 and L2 Cache access.
Some expensive CPU operations are also in this range.

Branch mispredict penalty can cause upto 20 CPU clock Cycles, which is also in this range.

## 10-100 ns
L3 cache access is at this range.

For a modern Apple M1 processor, accessing main memory is at the lower end of this range.

Main memory access is a few hunderd times slower than CPU cache access.

## 100-1000 ns
Cost of a System Call.

User program -> C library -> [Call goes to Kernal Space] Kernel

This System Call usually takes several 100 nanosecond.
It does not count the cost of executing the program.

MD5 hash to incode a 64 bit number.

## 1-10us 
1000 slower than a CPU register access

Context Switching between linux threads takes atleast a few microseconds.

From Process 1 to Process 2.
E.g. From user code to kernel code.
and from kernel code to user code.
This is a best case scenario.

For a new thread, it could take significantly longer.

Memory copy of 64KB of data from one location to another also takes a few microseconds.

## 10-100 us
We can include some higher level operations

Nginx takes about 50us to process a HTTP request.

Reading 1MB of data sequentially from main memory takes about 15us.

Reading a 8K page from a SSD takes about 100us.

## 100-1000 us
SSD write latency is about 10 times slower than read latency.
writing a page takes about a millisecond.

Intra-zone networking round trip takes about 100us.

A typical Memcache/redis get operation takes about 1ms of time (by the client).
This includes the network round trip measure.

## 1-10ms
Intra zone networking latency is about 5ms.
For example, from Availability zone 1 to Availability zone 2 of a region takes 5ms.

The Seek time of a HDD is about 5ms.
It takes time to move the arms.

## 10-100 ms
The network round trip between US-east and US-west, and US-east to Europe comes in this range.

Read 1GB sequentially from main memory.

## 100-1000ms
A slow hash function like bcrypt a password, takes about 300ms.
password -> Hash function (password hashing algorithm) -> Hashed Password
It renders brute force password decryption ineffective.

TLS handshake is usually between 250ms to 500ms.
It has several network round trips. So number depends on the distance between the machines.

The network round trip between US-west coast and singapore is in this range.

Reading 1GB from a SSD is also in this range.

## 1s
Transfer 1GB of data over the network within the same region takes about 10s.
